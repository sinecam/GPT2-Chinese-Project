# V4.6 Corrective Response-Only SFT

V4.6 is a short corrective run initialized from V4.5. It targets the failures measured by the frozen V2 benchmark:

- exact and short answers
- basic arithmetic and factual questions
- strict output formats
- correct early termination
- identity consistency and capability boundaries
- safety refusal and false-premise correction
- concise knowledge answers
- prompt-echo filtering

The builder does not copy V2 benchmark prompts into training. It rejects exact and highly similar prompts from both generated corrective rows and V4.5 replay data.

## Default Data Mix

The default output contains 20,000 unique rows:

| Group | Rows |
|---|---:|
| Exact reasoning, factual, and format | 3,500 |
| Safety and truthfulness | 1,600 |
| Identity and boundaries | 600 |
| Concise knowledge | 800 |
| Writing | 100 |
| Filtered V4.5 replay | 13,400 |

Within the 3,500 exact-answer rows, 82% are reasoning, 10% factual, and 8% strict format examples.

Do not add `eval/zh_generation_v2.jsonl` prompts or references to the training data.

This copies the checkpoint, training log, and benchmark report without deleting the working V4.5 directory.

```bash
archive_dir="archives/V4.5_$(date +%Y%m%d_%H%M%S)"
```

Keep the original V4.5 checkpoint directory. The archive is an additional rollback copy.

## 3. Build The V4.6 Mix

The command expects the V4.5 builder output at `data/raw/V4.5_quality_sft_mix.jsonl`.

```bash
python scripts/build_v46_corrective_mix.py   --input data/raw/V4.5_quality_sft_mix.jsonl   --out data/raw/V4.6_corrective_sft_mix.jsonl   --benchmark eval/zh_generation_v2.jsonl   --max_records 20000   --exact_records 3500   --safety_records 1600   --identity_records 600   --knowledge_records 800   --writing_records 100   --seed 46   | tee logs/V4.6_build_corrective_mix.log

records=$(wc -l < data/raw/V4.6_corrective_sft_mix.jsonl)
echo "V4.6 records: $records"
test "$records" -eq 20000 || {
  echo "Expected 20000 rows. Check the build summary and V4.5 input path."
  exit 1
}
```

The build summary should show:

- 20,000 total records
- 37 benchmark prompts loaded
- 6,600 corrective rows
- 13,400 replay rows
- filtered, duplicate, and benchmark-rejected counts

Do not continue if fewer than 20,000 rows were produced.

## 4. Prepare Response-Only Arrays

V4.6 uses a 512-token block because the target answers are deliberately concise. The model still retains its original 1024-token maximum context.

```bash
processed_dir="data/processed/V4.6_sp50k_sft_corrective_mix"

if [ -e "$processed_dir" ]; then
  echo "$processed_dir already exists; move it aside before rebuilding."
  exit 1
fi

python scripts/prepare_dialogue_response_only_sp.py   --tokenizer artifacts/tokenizer_zh_50k/spm_zh.model   --input data/raw/V4.6_corrective_sft_mix.jsonl   --out_dir "$processed_dir"   --block_size 512   --val_ratio 0.02   --min_answer_chars 1   --max_answer_chars 600   --default_system "你是一个中文AI助手。回答要简洁、准确。身份问题只回答你是中文AI助手，不要编造姓名、职业或真实人物身份。"   --add_bos   --add_eos   | tee logs/V4.6_prepare_response_only.log
```

Verify the prepared files:

```bash
python -c "import json, numpy as np; p='data/processed/V4.6_sp50k_sft_corrective_mix'; m=json.load(open(p+'/meta.json')); tx=np.load(p+'/train_x.npy', mmap_mode='r'); ty=np.load(p+'/train_y.npy', mmap_mode='r'); vx=np.load(p+'/val_x.npy', mmap_mode='r'); vy=np.load(p+'/val_y.npy', mmap_mode='r'); print(m); print('train:', tx.shape, ty.shape); print('val:', vx.shape, vy.shape); print('supervised train tokens:', int((ty != -100).sum())); print('supervised val tokens:', int((vy != -100).sum()))"
```

Expected approximate shapes are 19,600 training rows and 400 validation rows, each with block size 512. Exact split counts can vary slightly.

## 5. Train V4.6

This starts a fresh optimizer from V4.5 weights. Do not use `--resume`.

The initial run is 1,200 iterations. It keeps model-only snapshots at iterations 400, 800, and 1200 so generation quality can be compared independently of validation loss.

```bash
out_dir="checkpoints/V4.6_sp50k_gpt2small_sft_corrective_mix"

if [ -e "$out_dir" ]; then
  echo "$out_dir already exists; move it aside before starting a new run."
  exit 1
fi

nohup bash -c 'python -m torch.distributed.run --standalone --nproc_per_node=2   scripts/train_gpt2_small_zh_response_only.py   --data_dir data/processed/V4.6_sp50k_sft_corrective_mix   --out_dir checkpoints/V4.6_sp50k_gpt2small_sft_corrective_mix   --init_from checkpoints/V4.5_sp50k_gpt2small_sft_quality_mix/ckpt.pt   --max_iters 1200   --batch_size 8   --grad_accum_steps 4   --learning_rate 1.5e-6   --min_lr 3e-7   --warmup_iters 100   --lr_decay_iters 1200   --eval_interval 200   --eval_iters 100   --snapshot_interval 400   --weight_decay 0.1   --grad_clip 1.0   --dtype bfloat16   --seed 46'   > logs/V4.6_sp50k_gpt2small_sft_corrective_mix.log 2>&1 &

echo "training pid: $!"
```

Monitor it:

```bash
tail -f logs/V4.6_sp50k_gpt2small_sft_corrective_mix.log
```

The snapshots are model-only and therefore smaller than `ckpt.pt` and `latest.pt`, which also contain optimizer state.

## 6. Compare Every Milestone

Run the deterministic V2 benchmark against V4.5, each V4.6 snapshot, and the best validation-loss checkpoint:

```bash
python scripts/benchmark_zh.py   --model V4.5=checkpoints/V4.5_sp50k_gpt2small_sft_quality_mix/ckpt.pt   --model V4.6_0400=checkpoints/V4.6_sp50k_gpt2small_sft_corrective_mix/snapshot_iter_000400.pt   --model V4.6_0800=checkpoints/V4.6_sp50k_gpt2small_sft_corrective_mix/snapshot_iter_000800.pt   --model V4.6_1200=checkpoints/V4.6_sp50k_gpt2small_sft_corrective_mix/snapshot_iter_001200.pt   --model V4.6_best=checkpoints/V4.6_sp50k_gpt2small_sft_corrective_mix/ckpt.pt   --tokenizer artifacts/tokenizer_zh_50k/spm_zh.model   --suite eval/zh_generation_v2.jsonl   --out_dir reports/V4.5_vs_V4.6_zh_v2   --device cuda   --dtype bfloat16   --temperature 0   --max_new_tokens 160   --top_k 30   --top_p 0.85   --repetition_penalty 1.15   --no_repeat_ngram_size 4   --seed 20260620
```

Review:

```text

reports/V4.5_vs_V4.6_zh_v2/results.json
```

Choose the checkpoint by benchmark and blind-review results, not only by validation loss.

## 7. Promotion Gates

Do not replace the display checkpoint unless the selected V4.6 milestone meets all of these:

- automatic score is higher than V4.5
- rule score is at least 30
- critical-failure rate is below 5%
- truncation rate is below 35%
- identity does not regress
- safety/truthfulness has non-zero pass rate and no harmful compliance in raw responses
- factual and reasoning categories both improve from zero
- blind review confirms that concise answers and writing quality did not collapse

If iteration 800 is better than iteration 1200, use the 800 snapshot. More training is not automatically better.
